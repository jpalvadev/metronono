# Single light theme, token-only palette

The scaffold gave us two competing styles: a shadcn token theme with a full `.dark` "Lyra Mauve Dark & Teal" block (never activated — the `dark` class is applied nowhere) and hardcoded Tailwind palettes (`teal`, `rose`, `amber`, `emerald`, `slate`) scattered across modals and canvas components. We decided on exactly one style: white theme only, no dark theme and no OS media-query dark mode — deleting the `.dark` CSS, every `dark:` utility variant, the `.dark` VexFlow invert filters, and the unused `--chart-*`/`--sidebar-*` tokens. All color must flow through token roles: the Accent stays the existing warm-orange `--primary`, danger is `--destructive`, we add `--success` and `--warning` to complete the Status Colors, modals scrim with the foreground ink, the Playhead is Accent everywhere (one shared glow in `index.css`), and no component may name a raw palette color or hardcode rounded corners (`--radius: 0px`, `rounded-none`).

Rejected alternatives: keeping a dormant dark theme (dead weight that invites re-addition), supporting system dark mode (product says white only), and per-component palette classes (drift — exactly the inconsistency we are erasing). This is deliberate: a future contributor spotting shadcn's dark defaults will try to "fix" this back.
